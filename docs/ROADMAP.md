# Artio implementation task ledger

## Master Plan v5.1 implementation block

The v5.1 directive supersedes the v5.0 sequence for remaining work. Existing delivered items below remain delivered; do not repeat their audits or rebuild working paths. The new plugin-composition foundation blocks plugin-dependent feature work. Gates proceed in dependency order: **(1)** capability registry, v2 manifest and ADR; **(2)** instance/release identity migration and v1 compatibility; **(3)** scoped deterministic routing and immutable operation ledger; **(4)** payment/shipping historical ownership; **(5)** Kafka-backed Core-owned plugin event dispatcher; **(6)** object storage primary/replica orchestration and verified migration; **(7)** Backoffice, security and observability integration; **(8)** PostgreSQL + Kafka + Docker end-to-end acceptance. Each gate requires focused automated tests and its stated runtime evidence before closure. Docker verification must remove only resources created by that test run, including images and named volumes.

Development database policy: maintain exactly one current schema snapshot in `V1__initial_schema.sql`. Fold changes directly into that clean-install snapshot; do not add versioned schema upgrade scripts or claim pre-production database upgrade support. Production releases will introduce explicit upgrade history and tests. This policy does not change plugin manifest or API compatibility requirements.
