# Product SEO metadata v1

Products may store base-language canonical URL slug, SEO title and description. The slug is lowercase ASCII words separated by hyphens, up to 160 characters, and is unique across catalog products. The title is optional and capped at 180 characters; the description is optional and capped at 320. Each supported localized product translation (`de`, `it`, `fr`, `en`) may also have localized SEO metadata; localized slugs are unique within their locale.

Administrators update all SEO fields through `PUT /api/v1/products/{id}/seo` with `{ "slug": "brass-desk-lamp", "title": "Brass Desk Lamp", "description": "..." }`. The public product response includes the saved metadata for storefront routing and search rendering. Both the domain value and PostgreSQL constraint validate canonical slug syntax; a partial unique index enforces uniqueness. SEO changes record a `ProductSeoMetadataUpdated` domain event and update product timestamps. The Backoffice Products screen exposes a simple SEO editor.

The translation endpoint accepts `seoSlug`, `seoTitle` and `seoDescription` alongside localized name/description. Localized slug and copy use the same bounds and syntax rules. Localized product reads select SEO metadata in this order: requested locale, English translation, then the product's base SEO fields. Translation list and upsert responses include these values. Backoffice Translations edits the localized SEO fields with the translated copy. See [scheduled publication](scheduled-publication-v1.md) for adjacent product contract behavior.
