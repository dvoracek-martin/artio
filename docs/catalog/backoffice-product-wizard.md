# Backoffice product creation

The Backoffice uses the shared [Artio visual identity](../BRAND_IDENTITY.md): Sora typography, dark navy surfaces and cyan–indigo–violet primary accents. Navigation, readable tables, responsive forms and focus states use a dedicated Backoffice layout layer at `artio-backoffice/src/backoffice.css`.

`/products` is the searchable catalog. `/products/new` is a separate four-step creation page: essentials and first variant, category/brand/typed attributes, image upload and ordering, then review. Categories can be created and selected inline. JPEG/PNG previews stay in browser memory until creation; the first image is the cover. Each image accepts alternative text. Prices and stock remain in their existing administration areas.

`POST /api/v1/products/drafts` (ADMIN/SUPERADMIN) accepts `name`, `description`, `sku`, `variantName`, `variantSku`, `brandId`, `categoryIds` and `attributes`. At least one category is required. It creates the product as an inactive draft together with its first variant and classification in one database transaction. SKU or metadata errors roll back the entire draft. Existing `POST /products` semantics are unchanged.

The browser uploads selected images sequentially through the existing validated product media API. Activation, if selected, happens after all uploads succeed. During a failed upload, the current wizard retains the created product ID and completed uploads; Retry skips both product creation and completed uploads. Rejected pending images can be removed or replaced from the review step, while completed uploads remain protected. Returning to Products leaves the draft available for the existing media manager. Refreshing or leaving the page discards unsaved browser fields/files; uploaded media and the saved draft remain on the server. Leaving during an upload prevents the wizard from starting further uploads or activation once that in-flight request returns.

For standalone Angular development, `npm start` in `artio-backoffice` listens on port 4201 and proxies `/api/v1` to `http://localhost:8080`. Set `ARTIO_DEV_API_URL` before starting it to use another API endpoint. Deployed nginx continues to provide same-origin API access.

## Verification (2026-10-14)

- `npm run build` passed the Angular production build and bundle budget.
- `gradlew.bat :artio-rest-api:test --tests io.artio.api.catalog.media.S3MediaStorageTests --tests io.artio.api.catalog.media.ProductMediaServiceTests --no-daemon` passed all five focused media/storage unit tests.
- `gradlew.bat :artio-rest-api:integrationTest --tests io.artio.api.catalog.ProductDraftIntegrationTests -x :artio-rest-api:test --no-daemon` passed against a real PostgreSQL Testcontainer with no skipped tests. It verifies staff authorization, inactive product creation, category assignment, the first variant, required classification and complete database rollback on variant SKU conflict. The unit test task is excluded here to avoid running the separately verified suite again and sharing its Windows output files with another Gradle run.
- Browser verification used an isolated local PostgreSQL instance and the actual dev-profile API through the Angular proxy: sign-in, `/products/new`, SKU normalization, inline category creation, PNG preview/alt text, draft creation, upload and retrieval through the media manager all passed. A deliberately oversized image was rejected by the server; removing the pending image and retrying completed the original draft without creating a duplicate.
- Desktop and 390px mobile layouts were inspected. Mobile navigation collapses behind an accessible Menu button. Product actions use a keyboard-operable disclosure; dashboard product/order totals are fetched independently of catalog filters. Browser history and direct product-creation links use real URLs.
- The existing media manager retains the selected file until a successful upload, rather than clearing its required file input before submission. A second PNG was uploaded successfully through this form and both images were retrieved with their alternative text and dimensions. Product/media errors display the API's standard `message` field. Developer-mode prefills no longer replace the displayed identity of an already signed-in administrator.
- S3 adapter unit tests verify private object requests, configured prefix, exact uploaded bytes, read/delete and invalid-key rejection. A real external S3 bucket was not configured or provider-tested; the default filesystem upload path was exercised end to end. No production deployment was performed.
- `docker compose --env-file .env.example -f artio-docker/docker-compose.yml -f artio-docker/docker-compose.media-s3.yml config --quiet` passed with temporary placeholder bucket/access-key environment values. No real provider credentials were used.
